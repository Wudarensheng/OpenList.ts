# Plan: 网盘文件缓存系统重构

## Context

用户需要参考 OpenList Go 项目，实现从网盘供应商获取文件元数据并缓存到 D1 数据库，前端从 D1 拉取渲染。当前代码存在多个关键 bug：缓存过期从未检查、SQL 查询逻辑错误、分页未实现、并发请求无去重等。

## 实现方案

### 阶段 1：数据库 Schema 变更

**文件**: `src/models/schema.sql`, `src/models/init.ts`

1. 给 `files` 表添加 `parent_path` 列（消除所有 LIKE 查询）:
```sql
ALTER TABLE files ADD COLUMN parent_path TEXT DEFAULT '';
CREATE INDEX IF NOT EXISTS idx_files_parent_path_storage ON files(parent_path, storage_id);
```

2. 新建 `file_links` 表缓存下载链接:
```sql
CREATE TABLE IF NOT EXISTS file_links (
  storage_id INTEGER NOT NULL,
  path TEXT NOT NULL,
  url TEXT NOT NULL,
  headers TEXT DEFAULT '{}',
  expires_at TEXT NOT NULL,
  PRIMARY KEY (storage_id, path)
);
```

3. 新建 `request_locks` 表实现 D1 单飞（singleflight）:
```sql
CREATE TABLE IF NOT EXISTS request_locks (
  key TEXT PRIMARY KEY,
  started_at TEXT NOT NULL,
  expires_at TEXT NOT NULL
);
```

4. 更新 `init.ts` 添加迁移逻辑（检测列是否存在再 ALTER）。

### 阶段 2：新建缓存管理模块

**新文件**: `src/cache.ts`

核心函数：

```typescript
// 检查缓存是否有效
async function isCacheValid(storageId: number, path: string, env: Env): Promise<boolean>
// 查询 file_cache.expires_at，与当前时间比较

// 获取缓存的文件列表（直接子项）
async function getCachedFiles(storageId: number, path: string, env: Env): Promise<FileObject[]>
// SELECT * FROM files WHERE storage_id = ? AND parent_path = ? ORDER BY is_folder DESC, name ASC
// 关键：用 parent_path 精确匹配，不再用 LIKE

// 存储文件列表到缓存
async function cacheFiles(storageId: number, parentPath: string, files: FileObject[], expirationMinutes: number, env: Env): Promise<void>
// 1. DELETE FROM files WHERE storage_id = ? AND parent_path = ?
// 2. 使用 env.DB.batch() 批量 INSERT
// 3. UPDATE file_cache SET expires_at = now + expirationMinutes

// 获取单个缓存文件
async function getCachedFile(storageId: number, path: string, env: Env): Promise<FileObject | null>

// 获取缓存的下载链接
async function getCachedLink(storageId: number, path: string, env: Env): Promise<LinkResult | null>
// SELECT * FROM file_links WHERE storage_id = ? AND path = ? AND expires_at > datetime('now')

// 存储下载链接
async function cacheLink(storageId: number, path: string, link: LinkResult, expiresInSeconds: number, env: Env): Promise<void>

// 使缓存失效（精确到 parent_path）
async function invalidateCache(storageId: number, path: string, env: Env): Promise<void>
// DELETE FROM files WHERE storage_id = ? AND (parent_path = ? OR path = ?)
// DELETE FROM file_links WHERE storage_id = ? AND path = ?
// DELETE FROM file_cache WHERE storage_id = ? AND path = ?

// 使整个存储的缓存失效
async function invalidateStorageCache(storageId: number, env: Env): Promise<void>
```

### 阶段 3：重写 fs.ts 文件列表逻辑

**文件**: `src/routes/fs.ts`

**handleListFiles 重写流程**:
```
1. 解析请求: path, page, per_page, refresh
2. 获取 storage (getStorageForPath)
3. 如果 path == '/', 返回存储列表（虚拟文件夹）
4. 如果 !refresh:
   a. isCacheValid(storageId, path) → 检查 file_cache.expires_at
   b. 如果有效: getCachedFiles(storageId, path) → 返回缓存
   c. 如果过期: 继续步骤 5
5. 从 driver 获取: driver.list(relativePath, config)
6. cacheFiles(storageId, path, result.content, storage.cache_expiration)
7. 分页切片: content.slice((page-1)*perPage, page*perPage)
8. 返回结果，write 根据 userRole 判断
```

**handleGetFile 改进**:
- 增加缓存链接查询: `getCachedLink()` → 避免重复调用 `driver.link()`
- 修复 `write` 字段根据用户角色

**修复 getCachedFiles 查询**:
```sql
-- 旧（有bug）
SELECT * FROM files WHERE storage_id = ? AND (
  (path = ? AND is_folder = 1) OR
  (path LIKE ? AND path NOT LIKE ? AND is_folder = 0)
)

-- 新（用 parent_path 精确匹配）
SELECT * FROM files WHERE storage_id = ? AND parent_path = ?
ORDER BY is_folder DESC, name ASC
```

### 阶段 4：改进 refresh.ts

**文件**: `src/routes/refresh.ts`

1. 使用 `env.DB.batch()` 批量插入文件（替代逐条 INSERT）
2. 先写入新缓存，再删除旧缓存（消除空窗期）
3. 使用 `storage.cache_expiration` 而非硬编码
4. 添加进度回调（可选，给前端显示刷新进度）

```typescript
async function refreshStorage(storage: any, env: Env): Promise<any> {
  const driver = await getDriverInstance(storage.driver, JSON.parse(storage.addition));
  
  // 递归获取所有文件
  const files = await listAllFiles(driver, '/', JSON.parse(storage.addition));
  
  // 批量写入新缓存
  const stmts = files.map(f => env.DB.prepare(
    `INSERT OR REPLACE INTO files (id, path, parent_path, name, size, modified, ctime, is_folder, hash_info, storage_id)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)`
  ).bind(/* ... */));
  
  // 分批执行（D1 限制每批最多 100 条）
  for (let i = 0; i < stmts.length; i += 100) {
    await env.DB.batch(stmts.slice(i, i + 100));
  }
  
  // 更新缓存时间戳
  await env.DB.prepare(
    'INSERT OR REPLACE INTO file_cache (path, storage_id, expires_at) VALUES (?, ?, datetime("now", "+? minutes"))'
  ).bind('/', storage.id, storage.cache_expiration || 30).run();
}
```

### 阶段 6：链接缓存

**文件**: `src/routes/fs.ts`, `src/cache.ts`

1. 在 `handleGetFile` 中先查 `getCachedLink()`

6. **Phase 6**: 链接缓存 → 优化性能

## 验证方式

1. **Schema 迁移**: `wrangler d1 execute openlist-db --command="SELECT * FROM file_links LIMIT 1"` 确认表存在
2. **缓存命中**: 连续两次请求同一目录，第二次应从 D1 返回（检查响应时间差异）
3. **缓存过期**: 设置 cache_expiration=1，等待后请求应重新从 driver 获取
4. **分页**: 在大目录中请求 page=2&per_page=10，验证返回不同数据
5. **链接缓存**: 连续两次获取文件链接，第二次不应调用 driver.link()
6. **TypeScript 编译**: `npm run typecheck` 无错误
